# AI Pulse — five-minute demo script

A script to run **live** against a locally started app. Do not present staged or fake data as production data; everything below is generated by the seeded local database.

## Before you start (do this before the clock begins)

```bash
# Terminal 1 — backend
cd backend
pip install -r requirements.txt
python -m app.seed                 # resets + reseeds the local database
uvicorn app.main:app --reload      # http://localhost:8000

# Terminal 2 — frontend
cd frontend
npm install
npm run dev                        # http://localhost:5173
```

Open http://localhost:5173. All seeded accounts use password `pulse123`.

If asked, state plainly: this is a **local demo database** seeded by `python -m app.seed`.

---

## 0:00–0:40 — The problem and the product

Say: "Companies want to know how well their teams use AI, but asking people directly is sensitive — leadership must never be able to identify an individual. AI Pulse measures AI maturity per role and seniority, gives each employee their own report, and gives admins only aggregate, privacy-safe views."

Point at the three flows: employee diagnostic → personal report; employee improvement plan; admin dashboard with small-group suppression.

## 0:40–1:30 — Employee assessment and report

1. Sign in as `priya@northwind.test` → choose **Northwind Logistics**.
2. The diagnostic loads questions for **Support / junior** (`GET /diagnostic/questions`). Point out the question set is role- and seniority-specific.
3. Answer the multiple-choice questions (any options) and type a real sentence for the open question, then **Submit**.
4. The report shows name, **maturity level**, average score, risks, and **Next steps** for the Support role.

## 1:30–2:30 — Evidence and improvement plan (Stage 5)

Scroll to **"Your assessment evidence and improvement plan"**.

- **Skill areas and evidence:** every assigned question with *your* answer, its score, and the stored rationale where one exists. Point out the note explaining that MCQs have **no stored rationale** — the app says so rather than inventing one.
- **Improvement opportunities:** the areas below the 4/5 threshold.
- **Recommended next actions:** two to three concrete actions. Point out that each one cites the saved answer/score or risk flag it came from, and that the note distinguishes *saved evidence* from *generated text*.

If you submitted a low-scoring open answer that the mock model flagged, show the risk flag driving a recommendation.

## 2:30–3:10 — Deletion and refreshed results

1. On the same report, click **Delete my assessment data** and confirm.
2. The report reloads to an empty state — the evidence/plan section now shows the **"No assessment answers are saved…"** message instead of fabricated content.
3. Say: deletion is scoped to the **selected organization** and is authorized by the signed-in membership; there is no user ID in the request, so it can only ever delete your own data.

## 3:10–3:50 — Small-group privacy and the five-person threshold

1. Sign in as `asha@northwind.test` → **Northwind Logistics** (admin dashboard).
2. The dashboard shows **no departments** yet, because no department has five completed diagnostics (seeded answers are partial on purpose).

Say: "A department is only returned once **five distinct employees** have a complete, valid diagnostic. Below that, we return nothing at all for it — not even a count — and organization risk totals only count flags seen for at least five employees, from released departments only."

(Optional if time allows: submit full diagnostics for five Support members and re-open the dashboard to show Sales/Support appearing.)

## 3:50–4:30 — Regression tests: tenant authorization and seniority fix

Show the test files and, if you run them, the live result:

```bash
cd backend
python -m pytest tests/test_questions.py -q            # seniority filtering (Stage 4)
python -m pytest tests/test_api.py tests/test_privacy_deletion.py -q   # tenant + privacy + deletion
```

Point to:
- `test_admin_cannot_see_other_org` / `test_dashboard_cross_tenant_access_still_denied` — an admin of one tenant gets **403** for another tenant's dashboard.
- `test_junior_engineer_does_not_get_senior_questions` — senior questions are filtered out by seniority.

## 4:30–5:00 — Wrap-up

- Original feature: the **evidence-backed improvement plan** (`GET /reports/me/improvement`) that explains *why* each recommendation follows from the employee's own answers.
- Tests: the pytest suite covers the new plan, API behavior, privacy thresholds, and deletion; also run the full suite (`python -m pytest`) and `git diff --check`.
- Known limitations to name honestly: the admin dashboard UI is a JSON placeholder; deletion is single-organization pending client confirmation; the local `.env` secret is short and must be rotated for anything non-local; live LLM mode is untested.

## Do not do
